## v2.0.0 - 2026-10-28
### Major
* HTTP mode: URL path changed from /mcp to /db/{databaseName}/mcp, which allows targeting specific databases in a multi-database Neo4j instance.
All HTTP mode requests must now include the target database name in the URL path. The previous /mcp endpoint no longer exists.
NEO4J_MCP_DATABASE / --database are rejected in HTTP mode. Setting these in HTTP mode now causes a startup error.
STDIO mode: NEO4J_MCP_DATABASE no longer defaults to "neo4j". This configuration option now needs to be set explicitly when using STDIO. Set NEO4J_MCP_DATABASE=neo4j explicitly to preserve the previous behaviour.

* HTTP mode now accepts X-Neo4j-MCP-URI header to specify which Neo4j instance to connect to per-request. (#278)
NEO4J_MCP_URI env var is no longer required in HTTP mode — URI comes from the header instead.
Requests without a valid X-Neo4j-MCP-URI get 400 Bad Request.
X-Neo4j-MCP-URI added to CORS Access-Control-Allow-Headers.
Bolt URI passwords are now redacted from error messages.

* The Initialize request may now fail when connectivity cannot be verified, required plugins (such as APOC) are missing, or configuration is invalid, with descriptive error messages.

* Removed deprecated environment-variable aliases and CLI flags. Environment variables are now scoped with the `NEO4J_MCP_` prefix, while CLI flags use concise, unscoped names.

* Removed the option to list tools without authentication in HTTP mode. `tools/list` now always requires authentication.

Removed configuration:

| Type | Removed |
| --- | --- |
| Environment variable | `NEO4J_HTTP_ALLOW_UNAUTHENTICATED_TOOLS_LIST` |
| Environment variable | `NEO4J_MCP_HTTP_ALLOW_UNAUTHENTICATED_TOOLS_LIST` |
| CLI flag | `--neo4j-http-allow-unauthenticated-tools-list` |
| CLI flag | `--http-allow-unauthenticated-tools-list` |

Unauthenticated `ping` (`NEO4J_MCP_HTTP_ALLOW_UNAUTHENTICATED_PING`) is unaffected.

* The `list-gds-procedures tool` is no longer auto-included and a GDS availability check is done on each `tools/list` request. Whether it is exposed now depends on server-level and/or per-request configuration settings.
If the tool is only enabled by default and GDS is not installed, it is omitted from the `tools/list` response.
If the tool is explicitly requested and GDS is not installed, `tools/list` fails with a descriptive error.
If the GDS check cannot be completed because of a different issue, `tools/list` fails with that underlying error.

* HTTP mode no longer starts without `NEO4J_MCP_HTTP_ALLOWED_URIS` (or `--http-allowed-uris`). STDIO is unaffected.
List the Neo4j hosts clients may target in `X-Neo4j-MCP-URI`; other hosts are rejected.
Format: comma-separated `host[:port]`, no scheme, port defaults to 7687, `*.` wildcard for subdomains. Port ranges and CIDRs are not supported; an invalid entry stops the server from starting.
Example: `NEO4J_MCP_HTTP_ALLOWED_URIS=*.databases.neo4j.io,db.example.com:7688,10.0.0.5`

### Minor
* The server now supports selective tool filtering through the "NEO4J_MCP_TOOLS" environment variable or the "--tools" CLI argument.
These values are used to filter the tools returned in the "tools/list" MCP response. If not specified, all tools will be enabled.
You can pass multiple tools at once as a comma-separated list. Example: "--tools 'get-schema,read-cypher'".

* Add per-request tool filtering via two new HTTP headers:
- `X-Neo4j-MCP-ReadOnly: true|false`, restricts the advertised tool list to read-only tools for that request; invalid values return `400 Bad Request`
- `X-Neo4j-MCP-Tools: <comma-separated list>`, restricts the advertised tool list to the specified subset; unknown tool names return `400 Bad Request`
- When both headers are present they are applied as an intersection (read-only mode takes precedence)
- When neither header is set the behaviour is unchanged

* MCP requests are now bounded by a timeout, 3m by default and 30m at most.
- Set the server limit with `NEO4J_MCP_REQUEST_TIMEOUT` or `--request-timeout` (e.g. `45s`, `5m`)
- HTTP mode accepts a per-request `X-Neo4j-MCP-Request-Timeout` header, which can only lower the server limit; larger, non-positive, or malformed values return `400 Bad Request`
- Tool calls and `initialize` that run past the limit are cancelled and return a `request timed out after <duration>` error

### Patch
* Requirement checks now run only on MCP `initialize`.
